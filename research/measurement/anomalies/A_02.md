# Observation

Output length (max_tokens) from 16 → 256 (synthetic, 512 input, conc2, closed, 20 requests) causes request throughput to drop 63% (1.071±0.050 rps → 0.421±0.001 rps) and p50 latency to increase 3.7× (1.049±0.012s → 3.910±0.033s), p95 1.95s → 4.74s (2.4×), while token throughput increases 5.3× (17.1 → 107.7 tok/s) and TTFT is flat (0.39s → 0.43s, +10%), TPOT is flat (0.010–0.012s). Intermediate points are monotonic: o32 thr 0.939 p50 1.22, o64 thr 0.801 p50 1.618, o128 thr 0.612 p50 2.43.

In short: increasing decode length linearly increases latency and linearly decreases request throughput, but increases token throughput — a clear throughput/latency tradeoff with flat prefill.

# Reality Check

- **Realistic:** YES. Output 32–256 is typical for chat (short answer 32, medium 64–128, long 256). Input 512 is typical pref. Conc2 is realistic light load. No synthetic trick (no 4k output).
- **Plausible:** Decode-dominated cost is expected for autoregressive transformers without spec decoding; flat TTFT is expected (prefill not dependent on output).
- **Stress-test:** 256 is upper-realistic but not extreme (baseline high_memory used 256). 16 is stress-low.
- **Synthetic-only risk:** Low. Same thr vs out curve appears for ratio sweep with same input but different output.
